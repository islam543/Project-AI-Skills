## AI Team knowledge (ai-team-kb plugin)
One Confluence page where the team shares projects, findings and data that another employee could use. Link in `~/.claude/ai-team-kb/page_url`; local copy `~/.claude/ai-team-kb/page.md`; an index of it is printed below. Rules are in the page's "How to use this page" dropdown.
- **Every prompt, check relevance:** does this request touch a project, finding, dataset, or a link between projects? If not, ignore the page. If yes:
  - **Read** the relevant entries in the local copy first. If the copy is missing or over 1 day old, fetch the page with the Atlassian connector as HTML, save it to a temp file, and run `bash ~/.claude/ai-team-kb/refresh.sh <file>` (it rebuilds the copy and checks it). Entries are leads, not facts: check before relying on one.
  - **Propose a line only when it helps someone else**: a project others could link to, a finding that saves them work, a dataset they could use. Never the user's own next steps or to-dos. **Match first:** compare the work with every entry by what it does (inputs, outputs, line), not by its name; if it is a project already on the page, or feeds one, propose an `Update to <title>` line with the new facts (owning team, inputs, API, link), and if unsure, ask the user. Format: `- **Title** (updated YYYY-MM-DD): what it is and why it helps others.` Optional `Link:` (shareable only: Confluence, Jira, Drive, the team GitHub repo) and optional `Suggestion:` (an improvement, or a link to another project on the page). No names of people, no who-wrote-what, no local file paths; totals only (no group under 20), no credentials, ASSUMED for anything unconfirmed, every year states its basis (UY, AY, RY, CY, FY), no em dashes.
  - **Only on a yes:** add the line with a targeted edit, never by resending the whole page. Read the page draft as HTML (full detail) for fresh ids and the snapshot token. Call `updateConfluenceContent` with `edits`: if the only Inbox item is "(empty)", `replaceNode` its paragraph with `<p>...</p>`; otherwise `insertNodeAfter` the last Inbox `<li>` with `<li><p>...</p></li>`. Dry-run first and check that only the Inbox changed, then publish and refresh the copy. If the Atlassian tools offer no `edits` (only a tool that replaces the whole body), do not write: tell the user. After publishing, re-read the page and check that every entry outside the Inbox kept its id and text; if not, tell the user.
- **Skills:** `/ai-team-kb:kb-harvest` drafts lines from the user's notes, docs and recent sessions (first run: 60 days; then since the last run, so it can run daily). `/ai-team-kb:kb-sort` is for the page owner: moves Inbox lines into their sections.
